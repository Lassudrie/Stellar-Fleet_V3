## Bugs priorisés (hors combat terrestre)

### P0 — CI rouge / compat sauvegarde

#### Désérialisation : gestion de version trop stricte + test cassé

**Symptôme**
- Le test `Deserialization rejects future save versions` échoue : il attend un message correspondant à `/newer than supported/`, mais l’erreur produite est générique.
- Plus grave : `deserializeGameState` **rejette toute version différente de `SAVE_VERSION`**, ce qui rend la section “MIGRATION …” inatteignable (et casse potentiellement la compat ascendante).

**Preuves**
- Test : `src/engine/tests/engine.spec.ts:4538` (regex attendue).
- Implémentation : `src/engine/serialization.ts:1354` (coercition `saveVersion`), `src/engine/serialization.ts:1364` (rejet `raw.version !== SAVE_VERSION`), `src/engine/serialization.ts:1376` (début de la migration, actuellement inatteignable si `version` ≠ `SAVE_VERSION`).

**Impact**
- `npm test` échoue (CI rouge).
- Chargeur de sauvegardes potentiellement incompatible avec des sauvegardes d’anciennes versions (selon intention projet).

**Repro**
- `npm test`
- ou ciblé : `node --experimental-specifier-resolution=node --loader ./tools/tsSmokeLoader.mjs src/engine/tests/engine.spec.ts` (voir la sortie pour le test en échec).

### P1 — Robustesse sérialisation (tolérance de lecture)

#### `saveVersion` calculé mais ignoré (régression de tolérance)

**Symptôme**
- `deserializeGameState` calcule `saveVersion = Number(raw.version)` mais valide/compare ensuite `raw.version` directement (`isFiniteNumber(raw.version)` puis `raw.version !== SAVE_VERSION`).
- Un `version: "5"` (string) serait rejeté alors qu’il est numériquement valable, ce qui est incohérent avec une approche “lecture tolérante”.

**Preuves**
- `src/engine/serialization.ts:1354` (calcul de `saveVersion`) et `src/engine/serialization.ts:1361` / `src/engine/serialization.ts:1364` (validation/compare sur `raw.version` au lieu de `saveVersion`).

**Impact**
- Rejet inutile de certains formats JSON “valides” (ex: sauvegardes/exports modifiés, tooling externe, migrations manuelles).

### P2 — Tooling (qualité de signal lint)

#### TypeScript 5.8 non supporté par `@typescript-eslint/*` v7

**Symptôme**
- `npm run lint` affiche un warning : TS `5.8.3` n’est pas officiellement supporté par `@typescript-eslint/typescript-estree` (v7).

**Preuves**
- Sortie de `npm run lint` (warning de compat).
- Versions : `package.json` (`typescript: ~5.8.2`, `@typescript-eslint/*: ^7.18.0`).

**Impact**
- Risque de faux positifs / faux négatifs ESLint, voire de crash parsing selon les syntaxes TS utilisées.
